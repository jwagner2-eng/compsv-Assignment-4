For the timed challenge, I chose to use a set to keep track of the values
that had already appeared. I thought a set made the most sense because the
problem asked me to find the first value that appeared more than one time. As I
went through the collection, I could check whether each value was already in
the set. If it was, I could immediately return that value. If it was not, I
added it to the set and continued. Using a set also made the solution faster 
because it can quickly check if a value has already been seen.

The 30-minute time limit made me focus on finding a simple solution that I
understood instead of trying to make the program more complicated than it
needed to be. (which I did for most of the previous assignments) 
I spent some time thinking about which data structure fit the
problem before writing the code. Once I decided on a set, the rest of the
solution was fairly straightforward. The time limit also made testing important
because I wanted to make sure the solution worked without spending too much
time changing it afterward.

The main trade-off I made was keeping the solution simple. I focused on
correctly finding the first repeated value instead of adding extra features
that were not required. I tested the normal example along with cases that had
no duplicates, an empty collection, a duplicate at the beginning, and strings.
Overall, I think the time limit encouraged me to focus on the actual
requirements and choose a data structure that made the problem easier to solve.
